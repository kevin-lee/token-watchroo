# 0.1.0 ([m1](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am1) & [m2](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am2)) - 2026-09-13


The first release of **Token Watchroo** - a macOS menubar app that shows how much of each AI agent's usage window you have used and warns you before a window runs out. The ring in the menubar fills with the highest usage across your agents. Click it for a card per agent with session and weekly windows, per-model weekly windows for Claude Code, percentages, and reset times.

All business logic is Scala 3 compiled by **Scala Native** into a static library. A small **Swift 6** shell hosts it and owns the menubar item, the menu, notifications, and timers. There is no Java Virtual Machine (JVM) at runtime.

## Highlights

### Agents (#1)

Claude Code (subscription plan) and Codex (ChatGPT plan), auto-detected from the credentials the Command Line Interfaces (CLIs) already store. There is no sign-in inside the app.

- Claude Code: the `Claude Code-credentials` keychain item read through `/usr/bin/security`, then `https://api.anthropic.com/api/oauth/usage`.
- Codex: `~/.codex/auth.json` (or `$CODEX_HOME/auth.json`), then `https://chatgpt.com/backend-api/wham/usage`. When that call fails, Codex keeps working offline from the newest rollout log under `~/.codex/sessions`.

### Menubar ring and cards (#1)

The ring has four states: normal, warning at 80% (amber), critical at 95% (red), and exhausted (time until reset). Each agent gets a card with a plan badge, a status pill, session and weekly bars, and reset countdowns in your local time zone. The menu holds Refresh now, Launch at Login, and Quit.

### Notifications (#1)

System notifications fire once at 80% and once at 95% of a window, and once more when the window resets. They are deduplicated per window in `~/Library/Application Support/Token Watchroo/state.json`, so a restart never repeats one. Window identity tolerates reset-time drift, so a small server-side shift in `resets_at` does not look like a new window.

### Richer Claude plan badge (#3)

The badge used to be the keychain `subscriptionType` capitalised - a login-time snapshot that never showed the Max multiplier or the Team seat and went stale after a plan change. The provider now calls `GET /api/oauth/profile` next to the usage call and maps the live plan to "Max", "Max 5x", "Max 20x", "Pro", "Team", "Team Standard", "Team Premium", or "Enterprise".

- `organization_type` is parsed first, the multiplier comes from `rate_limit_tier` for Max only, the seat from `seat_tier` for Team only, and the account flags are used only when the organization type is missing or unknown.
- The profile result is cached per access token for an hour on scheduled ticks (failures included, keeping the last label for the same token) and refetched on a manual Refresh now. A profile failure never affects availability.
- Offline the keychain blob's `rateLimitTier` already reads "Max 5x", with the capitalised `subscriptionType` as the last resort.

### Per-model Claude weekly windows (#4)

The usage response's `limits[]` array is decoded, and every `weekly_scoped` entry with a display name and a non-null `resets_at` becomes an extra card row of 604800 s, for example "Weekly (Fable)". Rows are sorted by name, the first entry wins for a repeated name, and the fixed `seven_day_opus` and `seven_day_sonnet` keys are used only when `limits` is absent or null. Per-model windows count towards the agent status and the menubar ring like any other window, and they get their own notification copy ("Claude Code is near its weekly Fable limit").

### App icon and notification thumbnail (#5)

The kangaroo artwork under `design/logo/` is compiled by `scripts/generate-icons.sh` into `assets/Assets.car` (Aqua, DarkAqua, and Tintable stacks for macOS 26) and `assets/AppIcon.icns` (the light appearance for macOS 14 and 15). Both outputs are committed, so a normal build needs no Xcode.

On macOS 26 the dark kangaroo appears when System Settings > Appearance > "Icon & widget style" is set to Dark, or to Automatic at night. With the Default style the light kangaroo stays even in Dark Mode, which is how macOS 26 treats every app icon.

Every notification also carries a 256 px thumbnail drawing the alert ring at the percent the alert was built with - amber at 80, red at 95, and white with an empty arc on reset - so a banner shows the app icon on the left and the ring on the right.

### Signing, notarization, and distribution (#6)

- `scripts/bundle-app.sh` signs with the hardened runtime and a timestamp when `TW_SIGNING_IDENTITY` names a Developer ID Application identity, and stays ad-hoc otherwise. No entitlements are needed, and a signed rebuild no longer asks for the keychain "Always Allow" grant again.
- `scripts/notarize.sh` submits a `.app` or a `.dmg` with `notarytool` and an App Store Connect Application Programming Interface (API) key, prints the notary log on rejection, then staples and validates. `scripts/make-dmg.sh` builds `Token-Watchroo-<version>-<arch>.dmg` from the stapled app, signs it, and writes a `.sha256`.
- `.github/workflows/build.yml` runs the tests, an ad-hoc bundle, and a zipped bundle artifact on pull requests and pushes to `main`.
- `.github/workflows/release.yml` builds, signs, notarizes, and verifies an arm64 and an x64 DMG on `macos-26` and `macos-26-intel` for a `v*` tag, fails fast when a secret is missing, publishes the GitHub release with the checksums, and pushes the cask to `kevin-lee/homebrew-tap`. Both workflows declare read-only permissions, only the release job writes, and every action is pinned to a commit SHA.

## Privacy

- Nothing is written back to the credential files or to the keychain, and tokens never appear in logs or on cards.
- The only file the app writes is `~/Library/Application Support/Token Watchroo/state.json`, which remembers which notifications already fired.
- No telemetry, no accounts, no other network calls.

## Architecture

| Module                     | Platform                    | Purpose                                                                                                                                                                                                                                                                                                                                                                                         |
|----------------------------|-----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `token-watchroo-core`      | JVM and Scala Native, pure  | Domain model with refined4s newtypes and Scala 3 enums, status and menubar rules, the alert engine, International Organization for Standardization (ISO) 8601 parsing without `java.time`, notification copy through extras-render, jsoniter-scala codecs for the JavaScript Object Notation (JSON) contract, and the Codex rollout log parser. Tested with hedgehog property tests on the JVM. |
| `token-watchroo-providers` | Scala Native                | Keychain reader through `/usr/bin/security`, the `auth.json` reader, a libcurl Hypertext Transfer Protocol (HTTP) client with a malloc-backed write callback safe for the blocking extern call, and the Claude Code and Codex providers. Tested with munit.                                                                                                                                     |
| `token-watchroo-app`       | Scala Native static library | The exported C API (`tw_start`, `tw_refresh`, `tw_set_config`, `tw_shutdown`), the cats-effect runtime, the poll loop, alert state persistence, and the managed/unmanaged garbage-collector state switching that keeps the host main thread safe while it sits in the AppKit run loop. Tested with munit.                                                                                       |
| `swift/`                   | Swift 6 package             | A deliberately dumb shell that owns `NSStatusItem`, the `NSMenu` with custom agent card views, notifications, and Launch at Login, rendering the JSON envelopes the library sends through a callback.                                                                                                                                                                                           |

## Install

### Homebrew (recommended)

```bash
brew install --cask kevin-lee/tap/token-watchroo
```

### Disk image

Download `Token-Watchroo-0.1.0-arm64.dmg` (Apple Silicon) or `Token-Watchroo-0.1.0-x64.dmg` (Intel) from the [Releases](https://github.com/kevin-lee/token-watchroo/releases) page, open it, and drag **Token Watchroo** to Applications. The builds are Developer ID signed and notarized, so macOS opens them without a Gatekeeper step.

## Known limitations

- The usage endpoints are undocumented and may change. When they do, the card says "Unexpected response" instead of crashing.
- The app never refreshes tokens. When a token expires, run `claude` or `codex` once and the card recovers on the next refresh.
- A build from source is ad-hoc signed, so macOS asks to allow keychain access again after each rebuild. Click "Always Allow" once per build.
- No settings window. Thresholds are fixed at 80% and 95%, and the refresh runs every 60 seconds.
- The Scala Native optimiser is off, because the release-fast interflow pass miscompiles the first poller tick (#20).
- Cursor, Gemini CLI, and API-budget agents are on the roadmap.
