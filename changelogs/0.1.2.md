# [0.1.2](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am2b) - 2026-09-21


A stability release. The Codex card shows its percent again, a burst of "Refresh now" clicks no longer turns a card into "Unavailable", and three Scala Native runtime hazards found while testing the library under forced garbage collections are fixed or worked around. There is no Foreign Function Interface (FFI) change: the envelope `version` stays 1 and the Swift shell is unchanged.

## Bug Fixes

### Codex card showed "idle" instead of the percent (#53)

The Codex usage endpoint sends each window's reset time as `reset_at`, but the decoder read `resets_at` and skipped the unknown key, so every Codex window from the API had no reset time, the card showed "idle" at 0%, and no Codex notification could fire. `reset_at` is now decoded, with `resets_at` kept as a fallback and `reset_at` winning when both are present. The rollout log fallback is unchanged. The verified ChatGPT Team response is the main Codex fixture in the tests.

### Refresh bursts and rate limits (#51)

Clicking "Refresh now" several times in a row made every click a full manual tick with two HTTP calls, and a 429 from the usage API replaced the last good snapshot with "Unavailable" until a later scheduled tick recovered it.

- A refresh within 10 s after the end of the last manual tick is dropped, so a burst costs one tick and does not move the next scheduled tick. The refresh on opening a stale menu goes through the same window.
- Each provider keeps its last good snapshot per access token. On a 429, and only then, the card keeps its meters and shows "Usage API rate limited. Retrying next refresh." under them. Codex does this ahead of its rollout-log fallback. Every other error is "Unavailable" as before, and a token change never carries an old snapshot.

### A deadlock in Scala Native's weak reference handler (#43)

Scala Native 0.5.12's `PosixThread` allocates while holding its park mutex, and its `GC-WeakReferenceHandler` thread can deadlock when that allocation triggers a collection. The library carries a patched copy of that file which boxes the lock and condition pointers once at construction. It is pinned to Scala Native 0.5.12 and diffed on every upgrade.

### The libcurl write callback allocated on the Scala heap (#41)

libcurl calls the write callback while the thread is outside the garbage collector's view, and with the optimiser off the Scala callback boxed every argument on the Scala heap on every call, so a collection during a transfer could free or reuse those objects. The callback is now a C function with a malloc-backed buffer owned by C, copied into a Scala string only after the transfer ends. A growth failure aborts the transfer and is reported as out of memory.

### Envelope corruption in the release build, worked around (#44)

The Scala Native 0.5.12 garbage collector (GC) can lose a root of a thread stopped by a trap-based yieldpoint, the default for release builds, and then free a live object. In the library this corrupted an envelope's bytes during the conversion to a C string in about one forced-collection test run in twenty, and on the CI runners it also aborted or hung the test process. Reported upstream as [scala-native/scala-native#5046](https://github.com/scala-native/scala-native/issues/5046) with a standalone reproducer.

- Every binary is now linked with conditional yieldpoints (`SCALANATIVE_GC_TRAP_BASED_YIELDPOINTS=0`), which cuts the failure by a factor of about 25 on CI: 2 process deaths and no corrupted envelope in 840 forced-collection test runs (0.2 percent per run), against 4 to 7 percent per run and 60 percent of jobs failing with traps. The build refuses to load without the variable, checks the archive before staging it, and both workflows verify the mode of the shipped binaries with `nm`.
- Measured on the running app on 2026-09-20 (four 15-minute runs per mode, interleaved, on an 18-core Mac): 30 ms of CPU per refresh against 34 ms with traps, memory equal or lower, no GC warning. The mode costs nothing a user can notice.
- `Bridge.send` keeps verifying every conversion against the JSON bytes and redoing it on a mismatch, as a second net.
- This is a workaround, not a fix. The variable and the guards go together when a Scala Native release fixes #5046.

## For contributors

- The exported functions enter the cats-effect runtime once, in `tw_start`, and submit commands through a `Dispatcher` (#42), instead of an `unsafeRun*` call per export.
- `core` is a Scala Native only project and its hedgehog property tests run on Native (#48). The JVM half is gone.
- `BridgeSpec` (#40) replaces the forced-GC `PollerSpec` test that hung: it drives a real `Bridge` with a C recorder callback while a fibre forces collections and four fibres allocate, and hashes every envelope on arrival and after the callback. `CurlBufferSpec` (#41) does the same through the real libcurl write callback with a 4 MiB body. Neither is tagged flaky any more, and their timeouts are 120 s because the forced-collection storm runs about twice as slow under conditional yieldpoints on many-core machines.
- `SCALANATIVE_GC_TRAP_BASED_YIELDPOINTS=0` must be in the environment of the process that starts the sbt server, including the one Metals starts. The README's "Build and test" section has the recipe and the `TW_ALLOW_TRAP_YIELDPOINTS=1` opt-out.
- hedgehog `0.15.0`, hedgehog-extra `0.25.0`, sbt `2.0.9`.

## Install

### Homebrew (recommended)

```bash
brew install --cask kevin-lee/tap/token-watchroo
```

Already installed:

```bash
brew upgrade --cask token-watchroo
```

### Disk image

Download `Token-Watchroo-0.1.2-arm64.dmg` (Apple Silicon) or `Token-Watchroo-0.1.2-x64.dmg` (Intel) from the [Releases](https://github.com/kevin-lee/token-watchroo/releases) page, open it, and drag **Token Watchroo** to Applications. The builds are Developer ID signed and notarized.

## Known limitations

- The #44 workaround depends on a link-time variable: a build made without it carries the GC bug. The guards in `build.sbt` and in the workflows exist for that, and the official builds are verified with `nm`.
- Under conditional yieldpoints about one forced-collection test run in 400 still ends in a process death on the CI runners (#58). No corrupted envelope has been seen in 840 such runs, and the app itself never forces collections.
- The Codex Enterprise spend response shape is unverified. If the real response cannot be decoded, or decodes without a usable spend limit, Codex falls back to the newest rollout log and the card note shows "Unexpected response: ..." or "No usage limit reported by the usage API".
- The usage endpoints are undocumented and may change.
- The app never refreshes tokens. When a token expires, run `claude` or `codex` once and the card recovers on the next refresh.
- No settings window. Thresholds are fixed at 80% and 95%, and the refresh runs every 60 seconds.
- The Scala Native optimiser is still off (#20).
