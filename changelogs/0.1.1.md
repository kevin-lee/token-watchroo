# [0.1.1](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am2a) - 2026-09-14


A follow-up release to 0.1.0. Usage-based Claude Enterprise and Codex Enterprise plans now show their spend limit instead of two idle windows. The open menu stays correct when agents sign out or in, and errors from the Swift shell and the Scala Native library are now readable in the unified log and a log file.

## Bug Fixes

### Spend limit for usage-based Enterprise plans (#33)

On a usage-based Claude Enterprise plan the Claude Code card showed "Session" and "Weekly" rows, both idle at 0%, with an OK status, while the Claude usage page showed a monthly spend limit. Codex Enterprise had the same problem. The card layout now follows the usage response instead of the plan label.

- Claude: when `five_hour` and `seven_day` are both null and `spend` is enabled with a limit, the card shows a spend row and no session or weekly rows. Max and seat-based Enterprise plans keep their windows. The response has no reset time, so the reset is 00:00 UTC on the first of the next month, as described in the Claude Enterprise Spend Limits documentation.
- Codex: `rate_limit: null` maps to a spend row in credits from `credits` and `spend_control.individual_limit`. This response shape comes from public reports and is not verified on a real Codex Enterprise account yet.
- The spend row reads like the Claude usage page, for example "$0.05 of $200.00 spent" on the left and the percent with "resets Thu, Oct 1" on the right, with a bar. The currency uses the narrow symbol so it matches the usage page in every locale.
- The agent status and the menubar ring use the highest of the window percents and the spend percent, with the same 80% and 95% thresholds. An exhausted spend limit shows the time until reset in the menubar.
- A response with neither windows nor a spend limit shows "No usage limit reported by the usage API" instead of an OK card at 0%. Codex falls back to the rollout log in that case.
- Money is never a `Double`. Amounts are refined non-negative `BigDecimal` values with an International Organization for Standardization (ISO) 4217 currency code or credits, and the Swift shell decodes them as exact `Decimal` values.
- The Foreign Function Interface (FFI) change is additive. `AgentSnapshot` gains an optional `spend` field and the envelope `version` stays 1.

### Menu out of step with agents that sign out or in (#32)

After signing out of one agent while the menu was open, the menu showed the remaining agent twice, and the second card's note was clipped. After signing out of every agent, the menu kept the old cards and the menubar kept the old percent.

- Cards are updated in place only when the agent ids, their order, and the card heights match the new snapshot. Otherwise the open menu replaces the cards or the empty-state item. One agent signing out leaves one card at the correct height, signing in adds a card without closing the menu, and no agents show "No agent detected. Run claude or codex once.".
- The library left out `agents` when no agent was detected and `windows` for an unavailable agent. The shell could not decode that and dropped the snapshot. Both lists are now always sent, and the shell also treats a missing list as empty.

## Improvements

### Readable logs (#35)

Errors used to be logged with `NSLog`, which the unified log shows only as `<private>`, and a bundle started with `open` or from Finder lost everything written to stderr.

- The Swift shell logs through `os.Logger` with public text under the subsystem `io.kevinlee.tokenwatchroo` and the categories `core`, `notifications`, `launch`, and `app`. Read them with:
  ```bash
  /usr/bin/log show --predicate 'subsystem == "io.kevinlee.tokenwatchroo"'
  ```
  or in Console. In zsh `log` is a builtin, so spell out `/usr/bin/log`.
- Every dropped message from the library is logged with the reason (not UTF-8, undecodable head, stale `seq`, unknown type, or undecodable body with the coding path), its type, and its `seq`.
- A bundled app redirects stderr to `~/Library/Logs/Token Watchroo/token-watchroo.log`, so entry point failures and Scala Native runtime output survive. The file moves to `token-watchroo.log.1` at launch when it is larger than 1 MiB.

## For contributors

- A new XCTest target, `TokenWatchrooTests`, runs with `sbt swiftTest` and in the build workflow. It covers the open menu with two, one, and zero agents, snapshot and spend decoding, every drop reason of the envelope decoder, and log file rotation.
- `TW_DEBUG_CLAUDE_SIGNED_OUT_FILE` names a flag file. While it holds `signed-out`, the Claude credential reader reports missing credentials without touching the keychain, so a sign-out can be tested without signing out. The README describes how to use it.
- Enterprise and Max usage response fixtures and the unverified Codex Enterprise response are covered by hedgehog tests in core, and both providers are covered by munit tests with a fake `HttpClient`.

## Install

### Homebrew (recommended)

```bash
brew install --cask kevin-lee/tap/token-watchroo
```

Already installed:

```bash
brew upgrade --cask token-watchroo
```

### Disk image

Download `Token-Watchroo-0.1.1-arm64.dmg` (Apple Silicon) or `Token-Watchroo-0.1.1-x64.dmg` (Intel) from the [Releases](https://github.com/kevin-lee/token-watchroo/releases) page, open it, and drag **Token Watchroo** to Applications. The builds are Developer ID signed and notarized.

## Known limitations

- The Codex Enterprise spend response shape is unverified. If the real response cannot be decoded, or decodes without a usable spend limit, Codex falls back to the newest rollout log and the card note shows "Unexpected response: ..." or "No usage limit reported by the usage API". Without a rollout log the card is unavailable and shows the same message.
- On a Codex Enterprise account, that rollout log fallback can show session and weekly windows the plan does not have, with only the "from local log" note to tell them apart.
- The usage endpoints are undocumented and may change.
- The app never refreshes tokens. When a token expires, run `claude` or `codex` once and the card recovers on the next refresh.
- No settings window. Thresholds are fixed at 80% and 95%, and the refresh runs every 60 seconds.
- The Scala Native optimiser is still off (#20).
