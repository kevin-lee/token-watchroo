# [0.2.1](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am3-fix1) - 2026-11-06


This release fixes the Claude Code card for a keychain that has more than one Claude Code item. It is the first release that the app can install by itself.

## Upgrade

### From 0.2.0

The app finds this release by itself within a day, or now with "Check for Updates...". Choose "Install and Relaunch". This is the first real update through Sparkle.

With Homebrew, `brew upgrade --cask token-watchroo` also works.

### From 0.1.x

A copy older than 0.2.0 has no self-update. Upgrade it once with Homebrew or with the disk image, as described in the [0.2.0 notes](https://github.com/kevin-lee/token-watchroo/blob/main/changelogs/0.2.0.md#upgrade-from-01x). After that, the app updates itself.

## Bug Fixes

### "No Claude sign-in (only MCP state)" while Claude Code was signed in (#90)

A login keychain can have more than one `Claude Code-credentials` item, for example old items with another account that older Claude Code versions or other tools left. The app read the item with no account, so macOS could give it an old item with only MCP state, and the card showed "Unavailable".

- The app now reads the item for the same account as Claude Code: `$USER`, else the login name, and `claude-code-user` when the name is missing or not valid.
- When no item has that account, the app reads the item with no account, as before.
- If your keychain has more than one such item, macOS can ask once for keychain access after the update. Click "Always Allow".

## Install

### Homebrew (recommended)

```bash
brew install --cask kevin-lee/tap/token-watchroo
```

### Disk image

Download `Token-Watchroo-0.2.1-arm64.dmg` (Apple Silicon) or `Token-Watchroo-0.2.1-x64.dmg` (Intel) from the [Releases](https://github.com/kevin-lee/token-watchroo/releases) page, open it, and drag **Token Watchroo** to Applications. The builds are Developer ID signed and notarized.

## Known limitations

- A custom `CLAUDE_CONFIG_DIR` is not supported yet. Claude Code then keeps the sign-in in an item whose name has a hash suffix, and the app does not read it (#91).
- On Intel, the forced-collection test `BridgeSpec` still fails in about one run in 20 (#67). It has not been seen in the app, which never forces collections.
- The usage endpoints are undocumented and may change.
- The app never refreshes tokens. When a token expires, run `claude` or `codex` once and the card recovers on the next refresh.
- No settings window. Thresholds are fixed at 80% and 95%, and the refresh runs every 60 seconds.
