# [0.3.0](https://github.com/kevin-lee/token-watchroo/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am3a) - 2026-11-09


The app now has a settings window. You can set the alert levels of each agent, get alerts for spend limits, change the refresh interval and the card order, and choose the Claude Code config folder. Usage has a new blue colour band, and the default alerts are now at 70% and 85%. The app is now in English and Korean. The envelope `version` stays 1, and the Foreign Function Interface (FFI) only gains additive fields.

## New Features

### Settings window (#8, #100, #104)

"Settings..." (Cmd+,), below "Refresh now", opens the settings window.

- **Agent list.** The list shows each agent with its billing, its plan and an "Enabled" checkbox. The app adds each detected agent to the list. Clear "Enabled" to hide an agent and its card.
- **Add Agent... and Edit...** open a sheet with the billing (subscription plan or API) and the plan (Individual, Team or Enterprise). The plan fills the card badge only when the provider gives no plan label. The provider's label always wins, because it is the account's real plan.
- **API billing** is not supported yet. An agent with API billing shows an "unavailable" card that says so (#14).
- **Refresh interval.** "Refresh every" has 1 min, 2 min, 5 min, 10 min, 30 min and 1 h. The default stays 1 min.
- **Card order.** Move Up, Move Down and drag and drop change the order of the list, and the cards follow it at the next refresh.
- **Fewer fetches.** A change of the order, the plan or the interval does not fetch at once. The next refresh shows it. Many fetches in a short time can make the Claude usage API refuse requests for a short time (HTTP 429).

The settings are in `config.json` in the app's state folder. The app writes the file only after a change. A file that cannot be read is moved to `config.json.bad`, and the app starts with the defaults.

### Alert levels for each agent (#9)

The Add/Edit sheet has an "Alert at" row for the usage windows of an agent.

- Up to 5 levels, whole percents from 1 to 100, strictly increasing and at least 5 apart. The default is 70% and 85%.
- Remove all levels for no window alerts and no reset alerts for that agent.
- A level fires when the shown percent crosses it. When one refresh crosses more than one level, only the highest one fires. Each level fires at most once in a window.
- A change of the levels does not fire an alert by itself.

### Alerts for spend limits (#105)

A Claude monthly spend limit and a Codex credit limit now send alerts, for example "Claude Code is near its monthly budget" with "$246.00 of $300.00 spent, 82%. Resets in 19 days."

- The default levels are 70% and 85% of the limit, so they follow the limit when it changes.
- In the sheet, "Spend alerts" can be set to amounts in the limit's unit, for example 150 and 180 USD, or to no levels. The amounts can be set after the first refresh reads the limit.
- A "budget reset" alert comes when a level fired before the meter started again.

### Colour bands for usage (#101, #9)

The usage colours are now bands on the shown whole percent:

| Shown percent | Colour | Pill |
|---|---|---|
| Under 50 | none | OK |
| 50 to 69 | blue | Over half |
| 70 to 84 | amber | Near limit |
| 85 and more | red | Almost out |

An exhausted window shows as before. The bands apply to the ring, the card border, the bars, the percent text and the notification tile. A spend takes the band of its percent of the limit. The notification title follows the band: "is almost out" in the red band, else "is near its ... limit".

### Claude Code config folder (#91)

When you run Claude Code with `CLAUDE_CONFIG_DIR` (or `CLAUDE_SECURESTORAGE_CONFIG_DIR`), it keeps the sign-in in another keychain item. The app starts from launchd and cannot see your shell variables, so you now set the folder in the Claude Code sheet: "Config folder", with a text field and "Choose…".

- Use the same text as the variable. Claude Code uses the exact text: a trailing slash, a symbolic link or `~` gives another item. The app also tries the folder with its trailing slash added or removed.
- When a folder is set, the app never reads the default item, so a wrong folder never shows another account's usage. The card then says "No Claude Code sign-in for the Config folder in Settings. Check the folder or use /login."
- Leave the field empty for the default sign-in.

### English and Korean (#10)

The menu, the cards, the settings window, the notifications and the About panel are in English and Korean. The language comes from macOS: the Preferred Languages list, or the per-app language in System Settings > General > Language & Region > Applications. Sparkle's update windows and the AppKit words of the About panel follow the same language. Numbers and money follow the macOS region. A change of the language or the region shows after the app is restarted.

Plan names, agent names, model names, `claude`, `codex`, `/login` and the environment variables are not translated.

### "Claude Code sign-in expired" (#94)

When the Claude Code sign-in expired, the card said "Keychain item has no access token. Run claude to sign in." It now says "Claude Code sign-in expired. Run claude and use /login to sign in again." Two other messages now also say to use `/login`, because running `claude` alone does not fix them.

## Bug Fixes

### The About panel opened behind other apps (#97)

"About Token Watchroo" opened the panel behind the windows of the frontmost app. It now opens in front, as the settings window does.

### The reset alert came at every second reset (#110)

When a level fired in each window, the reset alert, for example "Claude Code session reset", came at every second reset. It now comes at every reset after a fired level. This bug was found before release in the new spend alerts too, and is fixed there.

## For contributors

- The shell's strings are in `swift/Resources/{en,ko}.lproj/Localizable.strings`, and the core's strings are in `messages_en.properties` and `messages_ko.properties`, embedded in the static library. Tests check that both languages have the same keys and placeholders (#10).
- The static library now needs CoreFoundation, for the Unicode normalisation of the Claude Code config folder (#91).
- The code follows the [2020 Hindsight Scala](https://2020-hindsight-scala.kevinly.dev/docs/) practices (#96).
- A test bug in `CurlBufferPatternSpec` that could fail CI is fixed (#112).

## Install

### Homebrew (recommended)

```bash
brew install --cask kevin-lee/tap/token-watchroo
```

### Disk image

Download `Token-Watchroo-0.3.0-arm64.dmg` (Apple Silicon) or `Token-Watchroo-0.3.0-x64.dmg` (Intel) from the [Releases](https://github.com/kevin-lee/token-watchroo/releases) page, open it, and drag **Token Watchroo** to Applications. The builds are Developer ID signed and notarized.

## Upgrade

### From 0.2.x

The app finds this release by itself within a day, or now with "Check for Updates...". Choose "Install and Relaunch".

With Homebrew, `brew upgrade --cask token-watchroo` also works.

### From 0.1.x

A copy older than 0.2.0 has no self-update. Upgrade it once with Homebrew or with the disk image, as described in the [0.2.0 notes](https://github.com/kevin-lee/token-watchroo/blob/main/changelogs/0.2.0.md#upgrade-from-01x). After that, the app updates itself.

### What changes at the upgrade

- **New alert levels.** The default alerts are at 70% and 85% of a window, not at 80% and 95%. An alert that already fired in 0.2.x does not fire again. A window that is already at or over a new level at the upgrade does not get that alert in its current window, because the usage did not cross the level. The next window works normally.
- **Spend alerts.** A spend that is already at or over 70% or 85% of its limit gets that alert at the first refresh, because spends had no alerts before.
- **The settings list.** The app adds each detected agent to the settings list at the first refresh, and writes `config.json` in its state folder.

### Going back to 0.2.x

0.2.x does not read `config.json`, so it uses its fixed settings. When a level other than 70 or 85 fired in 0.3.0, 0.2.x cannot read `state.json` and starts with an empty alert state once, so alerts in the current windows can fire again.

## Known limitations

- Agents with API billing are not supported yet (#14).
- One Claude Code card only, for one config folder.
- The per-app language in System Settings was not tested with a release build. The Korean check used the Preferred Languages setting for the app.
- On Intel, the forced-collection test `BridgeSpec` still fails in about one run in 20 (#67). It has not been seen in the app, which never forces collections.
- The usage endpoints are undocumented and may change.
- The app never refreshes tokens. When a token expires, run `claude` or `codex` once and the card recovers on the next refresh.
